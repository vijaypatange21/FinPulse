01 — PROJECT OVERVIEW & VISION
Project Overview & Vision
FinPulse is an AI-powered financial intelligence platform designed to help lenders and borrowers make smarter
decisions using real-time ML-driven insights. The platform ingests raw banking and transaction data, processes it
through a multi-stage feature pipeline, scores users across five predictive models, and surfaces results via dedicated
dashboards and REST APIs.
Core Objectives
• Provide a real-time Financial Health Score (0–100) for every borrower.
• Predict Loan Default Risk with probabilistic output (Safe / Watch / High Risk).
• Detect Transaction Anomalies and potential fraud in real time.
• Forecast Cash-Flow over 7–30 day horizons to surface EMI failure risk.
• Generate personalised Wellness Recommendations to improve financial health.
• Serve all insights via secure REST APIs and role-based dashboards.

Design Principles
PrincipleDescription
ModularityEach ML model is an independent microservice; upgrades to one do not affect others.
Feature ConsistencyA dual offline/online feature store ensures training and inference use identical feature definitions.
ExplainabilityGradient-boosted models and rule-based recommendation engines prioritise human-readable outputs.
ScalabilityContainerised services behind load-balanced Prediction APIs scale horizontally on demand.
ObservabilityEvery model endpoint is wrapped with latency tracking and accuracy-drift monitoring.

Pipeline Architecture
Batch jobs run nightly via Airflow, computing features over the preceding 24-hour window and materialising them to
the offline Parquet store. A streaming Kafka consumer continuously updates the online Redis store with the latest
account balance and recent transaction signals to support sub-second real-time scoring.

06 — PHASE 3: MODEL DEVELOPMENT & TRAINING
Phase 3 — Model Development & Training
Duration: Weeks 5–10 │ Team: ML Engineering
Phase 3 covers the full ML lifecycle for all five models: data assembly, experimentation, hyperparameter tuning,
evaluation, and registration in MLflow. Models are promoted to staging only after meeting agreed KPI thresholds.
Financial Health Score
AlgorithmXGBoost Regressor (baseline: Linear Regression)
InputsMonthly income/expense, savings rate, EMI/Income ratio, cashflow volatility, credit history length
KPIsRMSE < 5, R² > 0.85
NotesTrain on 12+ months of historical data. Use 5-fold cross-validation. Apply SHAP for feature importance.
Loan Default Risk
AlgorithmXGBoost Classifier (baseline: Logistic Regression)
InputsHealth Score, missed EMI count, income variance, expense spikes, active loan count
KPIsAUC-ROC > 0.90, KS statistic > 0.40
NotesHandle class imbalance with SMOTE. Calibrate probabilities using Platt scaling.
Transaction Anomaly Detection
AlgorithmIsolation Forest (alternative: One-Class SVM)
InputsTransaction amount, time-of-day, merchant category, post-transaction balance, frequency patterns
KPIsPrecision > 0.85 @ 5% FPR on labelled holdout
NotesUnsupervised — no ground-truth labels required for training. Validate on a manually labelled fraud set.
Cash-Flow Forecasting
AlgorithmARIMA (production), LSTM (v2)
InputsDaily balance time-series, salary deposit dates, recurring expense dates, EMI payment schedule
KPIsMAPE < 8% over 7-day horizon, < 15% over 30-day
NotesUse pmdarima for auto-ARIMA. LSTM requires GPU; train offline and export to ONNX for serving.
Wellness Recommendation
AlgorithmDecision Tree / Rule Engine (max depth ≤ 5)
InputsSavings rate, category spend ratios, debt-income ratio, Health Score, risk class
KPIsCoverage > 95% of user states; explanation clarity audit
NotesKeep depth shallow for full explainability. Validate rules with financial advisors before deployment.
